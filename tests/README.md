# tests/

Automated tests that run locally in Node, with **no Google account and no live Sheet**.
Run them with `npm test` (or `npm run check` for type check + tests). Node's built-in
`node:test` runner; no test packages.

| Path | Holds |
| --- | --- |
| `helpers/load-src.js` | Loads every `src/*.js` into one shared `node:vm` sandbox, like Apps Script's single global scope. Read top-level `const` values with `get('NAME')`; wrap sandbox objects in `plain()` before `deepStrictEqual`. |
| `helpers/fakes.js` | Minimal fakes for `SpreadsheetApp`, `Session`, `HtmlService`, `Utilities`. Fake spreadsheets are plain tables; a **read-only** one (used for Meta-Data) throws on any write. Where the code depends on Google's behaviour, the fakes copy it. |
| `fixtures/meta-data.js` | The live Meta-Data sheet's **shape** with **made-up amounts**. The owner's real targets never go in git. |
| `*.test.js` | One file per `src` area, plus `fakes.test.js` and `load-src.test.js`. |
| `browser/*.check.js` | `npm run check:browser`: the owner's Links window, and the salesman's page end to end (real `doGet` and server code on fake sheets, Chromium at 360px): adding (`app`), updating (`update`), the save queue (`queue`), the tabs, search and target (`tabs`, spec 006), the card helpers, Snooze and the area filter (`cards`, spec 007), the admin's screen and his Updates (`admin`, spec 008), and both Summary screens (`summary`, specs 009 and 010: tiles, target bar, tables, the team table at 360 px, the WhatsApp link, Copy and its fallbacks, no signal, Back; spec 011: the logo strip, a tile / NOW row → its site list → a site → Back / Save to the list → Back to the summary where he was, "+ N no longer in your list", named rows, region summaries, ‹ Prev / Next ›, a card of a site won last month, and the wide layout at 1280 px). The admin's check also drives the Plan tab (spec 011); `daily` drives the Daily message (spec 012: the button on Today, the last working day, ‹ / › to 31 days back and today "(so far)", the pills with no trip and the last one remembered, today never kept (midnight, the 10-minute refresh), a summary reply landing on this screen, the server's exact text, the WhatsApp link, Copy and its fallbacks, no signal, Refresh clearing the kept days, Back to Today where he was, storage blocked, 360 px and 1280 px); `contacts` drives the new contact person (spec 011: Earlier contacts, + New contact person, Make main, "Is this a new person?", search, a carried contact change, the admin's feed). Every check opens pages through `doGet`, so it tests the served (stripped) page. Not part of `npm test` (needs Playwright). |

Rule: new logic gets tests; new server functions get a test that a salesman only sees his own
data (ADR-0004). `admin.test.js` (spec 008): every `adminPage…` function gives nothing to a junk
code, a salesman's code or a cancelled admin code; it reads `Activity` only from the bottom. `summary.test.js` (spec 009): periods, every count, both won / lost rules, team totals, exact WhatsApp wording, privacy, the kept copy's last month, revised prices recorded only when changed, what a summary costs; spec 010's parts, exact WhatsApp texts (monospace lines ≤ 30 characters, columns aligned) and millions. `served.test.js` (spec 010): `servedHtml_`'s rules, the page data untouched, every served script parses and equals the source's code lines, and the served-size pins (spec 011: salesman ≤ 84,000 bytes; spec 012: admin ≤ 111,200), and no top-level function name twice in `App.html` + `Admin.html` (one scope). `summary.test.js` (spec 011): every tile and NOW row's site list adds up to its count for every period and view, list order and period lines, privacy (his own summary never sends a site that is no longer his), regions equal their team-table rows, the admin's cards of closed sites, and the reply size (three times a busy month ≤ 150 KB). `admin.test.js`: each salesman's last save day (Plan). `interleave.test.js`: "two people, one site" in 1,500 seeded random interleavings (a model of the page's save queue using App.html's own update rules, against the real server); `SEED=<n>` reruns one, `SEEDS=<n>` runs more. `interleave.test.js` since spec 011 also makes new contact persons, Make main, × and empty boxes, carried into forms opened over queued saves: never a person lost or kept twice, at most one `contact` row per save, a contact refused only when someone else changed it, and a save sends only the contact its form shows; the page's moveMain equals the server's Earlier contacts; seen.via stays ≤ 20 along a chain of 30 queued saves and includes his queued Edit details; a save of a site only the admin's summary brought never enters his sites (after a reload too). `daily.test.js` (spec 012): the Daily message's default day on every weekday, the 1st of a month and 1 January, rows at Pakistan midnight, the ‹ / › limits and "(so far)", a bad day refused before anything is read; every count (activity, New, Sample given, Quoted, Won / Lost per site as the day ended (an undone or admin-made win is nobody's), the lost reason's fallback, Followed up, the admin's and a former salesman's rows, handed-over and deleted sites, line breaks in names); exact texts and totals; privacy (ADR-0012) and refusals; what it costs. `contacts.test.js` (spec 011): the earlier contacts cell (reading odd lines, writing, at most 20), the Update and Edit details paths, repeats and conflicts, the duplicate check and privacy (a salesman never gets another's earlier contacts).
