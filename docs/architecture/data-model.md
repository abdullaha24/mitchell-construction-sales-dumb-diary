# Data model (Google Sheet)

> Status: **Draft v0.1**, from the brainstorm. Not final; several fields depend on
> [open questions](../product/open-questions.md). The Sheet's tabs and headers act as the app's
> database schema. **Any change here must be made in the same change as the code.**

Conventions:
- Row 1 of every tab is the header. Code finds columns **by header name**, never by position.
- IDs are generated by the app and never reused.
- Timestamps are written by the server, never typed by people.

## Tab: `Reps`, the salesmen (owner-maintained)

| Column | Example | Notes |
| --- | --- | --- |
| `rep_id` | `R03` | Internal ID. Not used in links. |
| `name` | Tariq | Shown in the owner's reports only. |
| `city` | Lahore | Islamabad / Lahore / Karachi. |
| `phone` | 03xx… | Optional. |
| `token` | *(long random)* | **Secret.** The private link key (ADR-0002). Consider keeping tokens out of the visible Sheet; to be decided. |
| `active` | TRUE | FALSE = link revoked. |

One row per change. **Never edited or deleted by the app.**

| Column | Example | Notes |

## Tab: `Lists`, pick-list values (owner-maintained)

So the owner can change buttons without code changes. Columns: `list` (e.g. `product`, `area`,
`lost_reason`, `buyer_type`), `value`, `city` (blank = all cities), `active`, `sort`.

## Not modelled yet
- Multiple contacts per site (v1 assumes one).
- Dealers with recurring orders (open question 1).
- Payment recovery / ugrahi (open question 2).
- Sites shared between salesmen (open question 9).
